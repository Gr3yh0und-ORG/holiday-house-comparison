# Review holiday-house-comparison / frontend (2026-10-28)
Reviewed commit: 7ce9e09. Files read: CLAUDE.md (all), README.md (first 80 lines), templates/index.html. Tests: not run (the task specified "run none"; no test command was executed).

## Summary
1. HIGH: Leaflet tooltips are built by raw string concatenation of scraped/config strings (`e.houseName`, `e.tripName`, `e.price`, `poi.label`, `run.name`, `loipe.name`) and passed as HTML — an existing `escHtml()` helper is not used there (templates/index.html:1056-1064, 1084, 1138, 1147, 1156).
2. MEDIUM: Outbound links (`house_url`, `direct_url`, `hut.url`, `sled_run.url`) are rendered into `href` with no scheme check, so a `javascript:` URL arriving through input.json or the scraper becomes a click-time XSS (templates/index.html:672, 675, 741, 745).
3. MEDIUM: The overview map draws only the *first* house's train track globally (`trainTrackSeen` flag, templates/index.html:1088-1093), and the house-map block renders on `is defined` alone (line 678), so a `None`/empty lat/lon produces a NaN map and a broken Google Maps link.

## Bugs

- **[HIGH] templates/index.html:1056-1064 — unescaped HTML in overview-map tooltips.**
  Quote: `+ '<b>' + e.houseName + '</b>'` … `.bindTooltip(tooltipHtml, { direction: 'top', offset: [0, -15] });`
  Why: Leaflet renders tooltip strings as HTML. `houseName`/`tripName` come from input.json and `price` from scraped data; any `<img onerror=…>`/`<script>`-bearing string executes on the published page (the public FTP target). The file already defines `escHtml()` (line 1359) but does not use it here.
  Fix: `+ '<b>' + escHtml(e.houseName) + '</b>'` and wrap `e.tripName` and `e.price` the same way.

- **[HIGH→MEDIUM] Same class at templates/index.html:1084, 1138, 1147, 1156.**
  Quote: `.bindTooltip('🛷 ' + run.name, { sticky: true });` (also 1147, 1156), `.bindTooltip(poi.label || poi.type || 'POI', …)` (1138).
  Why: `run.name` is scraped from rodelwelten.com (third-party content) and `poi.label` from the scraper; both go into HTML tooltips unescaped.
  Fix: `escHtml(run.name)` / `escHtml(poi.label || poi.type || 'POI')` at each call site.

- **[MEDIUM] templates/index.html:672, 675, 741, 745 — no URL scheme validation on scraped/config links.**
  Quote: `<a href="{{ house.house_url }}" target="_blank" class="direct-link">`
  Why: Jinja autoescaping prevents attribute breakout but not `javascript:`/`data:` URIs. `house_url` originates in input.json and scraped broker pages; one malicious value yields click-time script execution. Also, none of the 7 `target="_blank"` links carry `rel="noopener noreferrer"`.
  Fix: validate in app.py (or a Jinja filter) that the URL starts with `http://`/`https://` before emitting, and add `rel="noopener noreferrer"`.

- **[MEDIUM] templates/index.html:1088-1093 — only the first train track is ever drawn.**
  Quote: `var trainTrackSeen = false;` … `if (trainTrackSeen) return; trainTrackSeen = true;`
  Why: unlike the sled-run dedup (`sledRunMap`, keyed by URL), the train track uses one global boolean, so the tracks of every later house (potentially different railways) are silently dropped from the overview map. The comment says "deduplicated", the code says "first only".
  Fix: key by track JSON like sled runs (`if (!seen[JSON.stringify(house.trainTrack)])`) or drop the flag and draw per unique track.

- **[MEDIUM] templates/index.html:678 (and 615/683) — house map and maps link check only `is defined`.**
  Quote: `{% if house.lat is defined and house.lon is defined %}`
  Why: the overview map guards with truthiness (`… and house.lat and house.lon`, lines ~999) but this block does not: `lat = None` or `""` renders `data-lat="None"` → `parseFloat` → `NaN`, a Leaflet map at NaN, and a broken `https://www.google.com/maps?q=,` link.
  Fix: `{% if house.lat and house.lon %}` in both places.

- **[MEDIUM] templates/index.html:851 — dead fallback language key.**
  Quote: `var t = window.ALL_TRANSLATIONS[window.CURRENT_LANG] || window.ALL_TRANSLATIONS['de'];`
  Why: translations are keyed `de-DE` (the picker and `formatDate` at line 839 both use `de-DE`); `'de'` never exists, so if `CURRENT_LANG` is ever missing every `T()` call silently returns the raw key path (e.g. "compare.button") instead of German.
  Fix: `|| window.ALL_TRANSLATIONS['de-DE']`.

- **[LOW] templates/index.html:775 — "None km" rendered.**
  Quote: `<span class="value">{{ loipe.distance_km }} km</span>`
  Why: the summary chip at line 762 guards with `{% if loipe.distance_km is not none %}`, the detail row does not; a loipe without a distance shows the literal `None km`.
  Fix: `{{ loipe.distance_km ~ ' km' if loipe.distance_km is not none else 'N/A' }}`.

- **[LOW] templates/index.html:515 vs 990 — trip colors disagree.**
  Quote: `{% set trip_colors = ['#2563eb','#16a34a', …] %}` (515) vs `var TRIP_COLORS = ['#2b6cb0','#276749', …];` (990)
  Why: the sidebar list item and the map marker for the same trip index use different palettes, so the color coding the sidebar implies does not match the map.
  Fix: emit the palette once (`window.TRIP_COLORS`) and use it in both places.

- **[LOW, unverified] templates/index.html:1001-1002 — raw numeric injection into JS.**
  Quote: `lat: {{ house.lat }},` / `lon: {{ house.lon }},`
  Why: if the scraper/cache ever yields `lat` as a string, this emits `lat: "47.3"`, and the later `house.lat.toFixed(5)` (line ~1036) throws, killing the whole overview-map IIFE. Not verified against real cache data; the backend may always coerce to float.
  Fix: `lat: {{ house.lat | float }},` (or `| tojson`).

- **[LOW, unverified] templates/index.html:840 — no guard for a bad date string.**
  Quote: `var d = new Date(dateStr + 'T00:00:00');`
  Why: an empty/`None` `checkin` renders as `data-date="None"` → `new Date("NoneT00:00:00")` → `NaN`, and the span shows `NaN.NaN.NaN`. Local-time parsing itself is correct (avoids the UTC off-by-one-day bug). Not verified whether input validation upstream rejects empty dates.
  Fix: `if (!dateStr || isNaN(d.getTime())) return dateStr || '';`.

## Implementation gaps

- **[MEDIUM] templates/index.html:1097, 1164 — hardcoded German, house-specific tooltip.**
  Quote: `.bindTooltip('🚞 Zahnradbahn Lauterbrunnen – Wengen (kein Auto, Parkplatz in Lauterbrunnen)', { sticky: true });`
  Why: the page is built for 9 languages and every other user-visible string goes through `data-i18n`/`T()`; this string ignores the language switcher entirely and hardcodes one specific house's railway into the shared template.
  Fix: move the text into a translation key (or into the house data) and read it via `T('…')`.

- **[MEDIUM, unverified] templates/index.html:1327-1328, 1383 — Jinja values interpolated raw into JS string literals.**
  Quote: `if (v === 'Available' || v === '{{ t.house.available }}')` (1327) and `.bindTooltip(houseMapEl.dataset.name || '{{ t.poi.house_label }}', …)` (1383)
  Why: a translation containing an apostrophe (e.g. a French label like `L'hébergement`) would break the entire `<script>` block — every map, filter and the compare modal die together. I checked all 9 translation files: none of these specific keys currently contains `'`, so the page works today; nothing enforces it stays that way.
  Fix: use `| tojson` instead of `'…'` (line 1330 already does this correctly for `check_manually`).

- **[LOW] templates/index.html:500, 508-510 — data-error warnings are not translatable.**
  Quote: `'msg': t.ui.room_warning_badge ~ ': ' ~ house.rooms ~ ' ' ~ t.ui.rooms_stated …`
  Why: the warning sentence is frozen in the build language and the `<li>` has no `data-i18n`, so switching to English keeps the warnings in German — inconsistent with the rest of the page which re-translates on the fly.
  Fix: store structured values + a `data-i18n` key on the `<li>` and rebuild the message in `setLang`.

- **[LOW] templates/index.html:1327-1328 — dead comparison branch.**
  Quote: `if (v === 'Available' || v === '{{ t.house.available }}')`
  Why: `HOUSE_DATA.avail` (line 1206, `avail: {{ house.time | tojson }}`) always holds the raw English status, so the translated-string alternatives can never match unless a translation literally equals "Available"/"Unavailable". Dead code that suggests a bug in the reader's mind.
  Fix: drop the `|| v === '…'` alternatives, or drop them together with the fix above.

- **[LOW] templates/index.html:880-899, 1264-1285 — persons filter and compare selection are unaware of each other.**
  Why: houses hidden by `applyPersonsFilter` stay checked and remain in `selectedHouses`, so the compare bar can offer a comparison of cards the user cannot currently see.
  Fix: in `applyPersonsFilter`, uncheck and remove hidden `.compare-cb` entries (or dim them).

No TODO/FIXME markers exist in the file. No secrets are hardcoded; the CARTO key is only present via `TILE_URL` from the build (line 831), matching the README's documented build-time injection (README lines 16, "read at build time and is visible in the page source") — consistent, not a finding.
