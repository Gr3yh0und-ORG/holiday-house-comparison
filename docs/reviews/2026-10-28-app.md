## Summary

1. `get_version()` (app.py:87) hard-codes the GitHub owner `Gr3yh0und` while the actual origin is `Gr3yh0und-ORG/holiday-house-comparison` — the rendered page's version can silently come from a different repository than the one deployed.
2. The `--house` patch path (app.py:909) stamps `updated_at = now()` even when the single scrape failed and returned cached/placeholder data, which resets the 24 h TTL used by `_load_cached_house` and can make stale data look fresh.
3. Cache reads are fragile against unexpected errors: `_load_houses_cache` (app.py:359) only catches `FileNotFoundError`/`JSONDecodeError`, and `_fetch_loipen` (app.py:214-217) crashes on a malformed cache entry (`KeyError`/`ValueError`) — a corrupt or hand-edited cache file can abort a build the README says is protected.

## Bugs

- **HIGH** — app.py:87 `get_version()`:
  `'https://api.github.com/repos/Gr3yh0und/holiday-house-comparison/releases/latest'`
  The repo's actual origin is `https://github.com/Gr3yh0und-ORG/holiday-house-comparison.git` (verified via `git remote -v`). The hard-coded `Gr3yh0und` repo also exists and currently serves `tag_name: 1.10.0` (verified with curl), so the page footer shows whichever tag that other repo carries — if the two repos ever diverge, the version shown is simply wrong, and the fallback chain (`git describe`) also depends on the checkout having the tags. Fix: drop the network call and reuse `_read_repo_version()` (the VERSION file, already the source of truth for health.json), or at minimum derive `owner/repo` from `git remote get-url origin`.

- **MEDIUM** — app.py:909 (`--house` path):
  `cached['updated_at'] = datetime.now().strftime('%Y-%m-%d %H:%M')`
  This runs unconditionally after the single-house scrape, even when `_scrape_one_house` returned stale cached data (app.py:424 `return cached`) or an all-`N/A` placeholder. `_load_cached_house` (app.py:363-372) computes the cache TTL from `updated_at`, so a failed `--house` run makes 3-day-old data pass the 24 h freshness check for another 24 h. Fix: only bump `updated_at` when at least one date group actually produced fresh data (e.g. track whether `_scrape_one_house` hit the cache/failure path), and skip the bump otherwise.

- **MEDIUM** — app.py:359 `_load_houses_cache`:
  `except (FileNotFoundError, json.JSONDecodeError):`
  A `cache/houses.json` that is unreadable for any other reason (`PermissionError`, `UnicodeDecodeError` from a non-UTF-8 write, `IsADirectoryError`) raises out of `--from-cache` — the mode deploys run — instead of being treated as "no cache". The README promises deploys never scrape and never lose data; a half-written file from a non-atomic external tool would crash the deploy with a traceback. Fix: `except (OSError, ValueError): return None` (`JSONDecodeError` is a `ValueError` subclass).

- **MEDIUM** — app.py:214-218 `_fetch_loipen`:
  `age = (datetime.now() - datetime.strptime(entry['fetched_at'], '%Y-%m-%d %H:%M')).total_seconds()` and `len(entry["loipen"])`
  `_read_cache` (app.py:202-208) handles a corrupt JSON file but not a corrupt entry: one entry missing `fetched_at`/`loipen`, or with a malformed timestamp, raises `KeyError`/`ValueError` and aborts the whole build. Fix: wrap the entry validation in `try/except (KeyError, ValueError, TypeError)` and fall through to a cache miss (refetch) on bad entries.

- **MEDIUM** — app.py:472 bus_stop distance string:
  `house_info['bus_stop'] = f"{poi['label']} ({d:.1f}".replace('.', ',') + f" km · {mins} min)"`
  The `.replace('.', ',')` is applied to the whole formatted prefix, not just the number, so a POI label containing a period (e.g. `"Haltestelle St. Johann"`) gets mangled to `"St, Johann"`. Fix: format only the number: `f"{poi['label']} ({format(d, '.1f').replace('.', ',')} km · {mins} min)"`.

- **LOW** — app.py:348 `_write_json_atomic`:
  `tmp_path = f'{path}.tmp'`
  Fixed temp-file name: two concurrent `app.py` runs (e.g. a `--house` patch while a scrape is still going) write the same `.tmp` and whichever replaces first wins, so a reader can get the other run's payload; no `os.fsync` before `os.replace` either. Fix: `tempfile.NamedTemporaryFile(dir=os.path.dirname(path), delete=False)` + `f.flush(); os.fsync(f.fileno())` + `os.replace`.

- **LOW** — app.py:136-140 `broker_name`:
  `if domain in url:`
  Substring match over the whole URL, not the host: any URL carrying another broker's domain in a path or query parameter (redirect/target params) is attributed to the first dictionary match. Fix: `host = urlparse(url).netloc; return next((n for d, n in _BROKER_NAMES.items() if host.endswith(d)), '')`.

- **LOW** — app.py:651-653 `_store_scrape_result` failure branch:
  `_write_health('down', previous['updated_at'] if previous else None)`
  Uses `previous['updated_at']` (KeyError on a hand-edited cache lacking the key) while every other read in the file uses `cached.get(...)`. Fix: `previous.get('updated_at')`.

- **LOW** — app.py:566 `_normalize_input`:
  `name = trip_entry['name']`
  A trip entry without `name` crashes with a raw `KeyError` traceback; same for `house['name']` at app.py:841 and 726-733. Since `input.json` is hand-edited (README step 3), a missing field should produce a pointed error message rather than a traceback. Fix: validate required keys up front and `raise SystemExit(f'input.json: house/trip missing "name": {...}')`.

## Implementation gaps

- app.py:900-914 (`--house` path) bypasses the §15B validation gate entirely: `_validate_scrape_output` and the `status`/`degraded` bookkeeping of `_store_scrape_result` never run, so a `--house` run whose scrape fails still rewrites `cache/houses.json` with the placeholder house and reports success. The README's failure semantics ("the run's status becomes degraded / down") only hold for the full scrape path. Fix: after patching, recompute `status` from the same failed/attempted stats the full path uses (thread `stats=` into the `--house` loop, which currently omits it — app.py:871).
- app.py:758-769 `index()` route is effectively dead code and unsafe as a server route: no `app.run()`/WSGI entry exists anywhere in app.py, so the Flask route is only reachable if someone serves `app` manually — and then it re-reads `input.json` (relative path, crashes without it), performs a full `build_trip_data` scrape (network + sleeps) per request, and calls `get_version()` (5 s network timeout) on every hit. Fix: delete the route, or gate it behind an explicit `--serve` flag with a cached render.
- app.py:26,385-388 `HOUSES_PARTIAL_FILE` is written after every house but only ever deleted on success (app.py:661-662); nothing reads it back. That matches the README ("a stopped or failed scrape never loses the last good data"), but the leftover file after a crash is misleading — a later `--broker` run overwrites it from scratch rather than resuming. Minor: either delete stale partials at scrape start, or state in the README that the partial file is informational only (the `/scrape` progress consumer).
- `load_config` (app.py:51-56) merges `config.json` over `_DEFAULTS` without any type validation: a `"fewo_cooldown_s": 30` (not a 2-list) crashes inside `build_trip_data` with an opaque `TypeError` at the first fewo house, and a negative `house_cache_ttl_h` silently disables the cache. Fix: coerce/validate the four known keys with a clear error message.
- No TODO/FIXME markers found in app.py (verified with grep). No secrets hard-coded: the CARTO key is read from env / homelab env file only (app.py:308-325), consistent with the README.

## Improvement suggestions

1. Make `get_version()` read the VERSION file via `_read_repo_version()` (or drop it and pass `_read_repo_version()` from `__main__`): removes a 5 s network call per run, the wrong-owner hard-coding, and the two-sources-of-truth problem between the page footer and health.json.
2. Route the loipen cache write (app.py:231) through `_write_json_atomic` — the helper exists three functions below and the raw `open(..., 'w')` is the only cache write in the file that is not crash-safe.
3. In `build_trip_data` (app.py:746), the fewo cooldown fires whenever the *just-scraped* house was fewo and the global limit isn't reached — including when no fewo house follows. Compare against the next scraped URL instead, or at least when the remaining queue contains fewo URLs, to avoid a pointless 20-45 s sleep at the end of a run.
4. `scrape_house` (app.py:275) hard-codes the `'N/A'` key list, duplicating `parsers.common.EMPTY` which is already imported as `_PARSER_EMPTY`; return `dict(_PARSER_EMPTY, room_config=[])` instead so a new parser field can't silently be missing here.
5. `_load_houses_cache` is re-read from disk inside `_load_cached_house` for **every** house during a scrape (app.py:365) — for ~50 houses that is 50 JSON parses of the same file. Parse once per run and pass the dict in, keeping a small mtime check if freshness matters.
