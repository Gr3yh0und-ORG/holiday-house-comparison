Reviewed commit: 7ce9e09. Files read: CLAUDE.md (first 80 lines), README.md (first 80 lines), parsers/common.py, parsers/booking.py, parsers/fewo.py, parsers/huetten.py, parsers/interhome.py, parsers/loipen.py, parsers/outdooractive.py, parsers/rodelwelten.py, tests/test_parsers_common.py, tests/test_parsers_house_pages.py. Tests: 30 passed, 0 failed (`pytest -q tests/test_parsers_common.py tests/test_parsers_house_pages.py`, 0.40s).

All findings below were verified by reading the code and, where marked "verified", by executing the exact code path in the dev venv.

## Summary
1. HIGH: A booked-out booking.com page with any stray `bui-price-display__value` element (recommendations, other units) flips the house to "Available" with a wrong price — directly contradicting the comment at booking.py:77-81 that promises never to take a price from other dates.
2. HIGH: A single bad numeric field silently corrupts or destroys an entire scrape: huetten.py:94 raises `KeyError: 'price_10'` when the price section is missing (whole house becomes 'Error'), and one non-numeric `altitude_to` in outdooractive.py:81 discards an otherwise complete result.
3. HIGH: Cache entries whose `fetched_at` is missing or malformed raise uncaught `KeyError`/`ValueError` out of `scrape()` in both rodelwelten.py:56 and outdooractive.py:48 — the try/except that handles scrape errors starts *after* the cache read, so one corrupted cache line kills the whole run.

## Bugs

### B1 (HIGH) booking.py:86 — stray price element overrides a booked-out verdict
Quote: `) and not soup.find('div', class_='bui-price-display__value')`
The comment at booking.py:77-81 says: *"The page then lists 'Ab € ...' offers for other dates and other houses, so never take a price from the free text."* But the `unavailable` flag is suppressed by **any** `bui-price-display__value` div anywhere on the page (recommended listings, other room types). Verified: a page whose room row says "An Ihren Reisedaten ... nicht verfügbar" plus one unrelated `<div class="bui-price-display__value">€ 999</div>` yields `time='Available'`, `price='€ 999'`.
Fix: scope the price check to the same rows that produced the "nicht verfügbar" text, e.g. only treat the page as priced if a `bui-price-display__value` exists inside a `tr` that also contains an `rt-name-link`.

### B2 (HIGH) huetten.py:94 — `KeyError: 'price_10'` when the Nebenkosten block exists but the price section does not
Quote: `result['total_costs_10'] = _sum_prices(result['price_10'], result['extra_costs_10'])`
`price_10` is only set inside `if price_sec and checkin_date:` (huetten.py:84-86), but the Nebenkosten block at :90 runs whenever `nk_div and checkin_date`. Verified: a page with a `div.Nebenkosten` and no price section raises `KeyError: 'price_10'`, the catch-all at :103 converts it to `{k: 'Error'}` — the entire house is lost even though location/rooms/bathrooms parsed fine.
Fix: use `result.get('price_10', 'N/A')`, or compute `total_costs*` only when both components were set.

### B3 (HIGH) rodelwelten.py:56 / outdooractive.py:48 — corrupted cache entry escapes the error handler
Quote: `age = datetime.now() - datetime.fromisoformat(entry['fetched_at'])`
The cache read sits **before** the `try:` (rodelwelten.py:61, outdooractive.py:58). Verified: an entry without `fetched_at` raises `KeyError: 'fetched_at'` out of `scrape()`; a non-ISO string raises `ValueError`. Since the cache is a JSON file on disk (`cache/`), one hand-edited or half-written line crashes the whole app run instead of re-scraping that URL. Same for a missing `'data'` key (returned at rodelwelten.py:59 / outdooractive.py:51).
Fix: wrap the cache lookup in `try/except (KeyError, ValueError, TypeError)` and fall through to a fresh scrape on any malformed entry.

### B4 (HIGH) common.py:7-22 + callers — module-level `EMPTY` shares mutable list values
Quote: `'room_config': [],` (common.py:13); also `EMPTY['track'] = []` / `EMPTY['huts'] = []` (rodelwelten.py:30-31, outdooractive.py:19-20).
`dict(EMPTY)` is a shallow copy: every caller who forgets to overwrite `room_config` mutates the module global. Verified: `dict(common.EMPTY); r['room_config'].append('junk')` leaves `'junk'` in `common.EMPTY['room_config']` for every subsequent house, and the same for `outdooractive.EMPTY['track']`. This is a silent cross-house data leak. (booking/fewo/huetten/interhome are currently safe because they pass `dict(EMPTY, room_config=[])`; the failure mode is triggered by any future caller and by the outdooractive/rodelwelten `track`/`huts` lists, whose `scrape()` error paths return `dict(EMPTY)` — outdooractive.py:41/56/148 — handing the same shared list to every caller.)
Fix: add a factory, e.g. `def empty_result(): return copy.deepcopy(EMPTY)`, and use it everywhere instead of `dict(EMPTY)`.

### B5 (HIGH) outdooractive.py:51 — cache hit returns the live cache object; callers corrupt the cache
Quote: `return entry['data']`
Verified: mutating `result['track']` on a cached scrape also mutates `_cache[key]['data']['track']`, which `save_cache()` (rodelwelten.py:47, outdooractive.py:36) then persists. Any downstream code that appends to `track`/`huts` permanently pollutes `cache/sledruns.json`.
Fix: `return copy.deepcopy(entry['data'])` (same at rodelwelten.py:59).

### B6 (MEDIUM) outdooractive.py:81-82 — one non-numeric altitude discards the whole result
Quote: `height_top = f"{int(alt_top)} m" if alt_top is not None else 'N/A'`
`int()` raises on any non-integer value (`'1.550'` as string, `'k. A.'`, `None`-like junk). Verified: `int('1.550')` → `ValueError`, caught by the catch-all at :146 → all 18 fields become `'N/A'`, even name/length/track that parsed fine. outdooractive serves strings as often as numbers here.
Fix: parse with a helper (`float(str(v).replace('.','').replace(',','.'))` in a try) and default that one field to `'N/A'`.

### B7 (MEDIUM) outdooractive.py:74-76 / rodelwelten.py:17 — dot-as-thousands-separator makes lengths 1000× too small
Quote (outdooractive.py:74): `m = re.search(r'\d[\d.]*', str(dist_obj))` → verified `'1.200'` (German for 1200 m) parses as `1.2` → reported length `0.0 km`.
Quote (rodelwelten.py:17): `val = float(m.group(1).replace(',', '.'))` → verified `_normalize_length('1.200 m')` returns `'0.0 km'`.
A `.` used as a thousands separator must be stripped when it is followed by exactly 3 digits and there is no `,` decimal.

### B8 (MEDIUM) huetten.py:204 — extra costs are only found when `€` precedes the amount
Quote: `amount_m = re.search(r'[€\u20ac]\s*([\d.]+(?:,\d+)?)', text)`
Verified: `'Endreinigung pro Aufenthalt 80,-- €'` (euro sign *after* the amount, a common German layout — the price table itself at :163 handles `'€ 2.090,--'` and the code elsewhere accepts `'X €'`) returns `N/A`, so `total_costs` silently becomes `'N/A'`.
Fix: make the euro sign optional/positional-tolerant: `r'(?:€\s*([\d.,-]+)|([\d.,-]+)\s*€)'` and pick the non-None group.

### B9 (MEDIUM) huetten.py:60 — bathroom sum counts per-room mentions
Quote: `bath_count = sum(int(m.group(1)) for m in re.finditer(r'(\d+)\s*Badezimmer', text))`
Verified: text "Dieses Haus hat 4 Badezimmer. Schlafzimmer mit 1 Badezimmer ensuite." → `bathrooms = '5'`. Summing *every* mention in the free page text inflates the count whenever the room list repeats the word.
Fix: restrict the sum to the summary line / equipment list element rather than the whole `text`, or take the max single match from the summary section.

### B10 (MEDIUM) interhome.py:173 — `'verfügbar' in badge_text` matches the negation
Quote: `result['time'] = 'Available' if 'verfügbar' in badge_text else 'Unavailable'`
Verified: `'Derzeit nicht verfügbar'` → `'Available'` (substring match). Today the loader waits for the known strings ('Deine Daten sind verfügbar' / 'leider ausgebucht', :57-59, :68), but any badge wording with "nicht verfügbar" reports a booked-out house as Available *with a price*.
Fix: `if 'verfügbar' in badge_text and 'ausgebucht' not in badge_text and 'nicht' not in badge_text` — or reuse the `_available` predicate from :57-59.

### B11 (MEDIUM) common.py:74 — `normalize_country(None)` raises `AttributeError`
Quote: `return _COUNTRY_NAMES.get(s.strip(), s.strip())`
Verified: raises on `None`. Reachable from production: booking.py:48 `addr.get('addressCountry', '')` returns `None` (not `''`) when the JSON has `"addressCountry": null` — verified — and booking's catch-all then turns the whole house into `'Error'` even though the JSON-LD parsed fine.
Fix: `s = (s or '').strip()`.

### B12 (MEDIUM) loipen.py:18-19 — circuit breaker + failure counter are process-global module state
Quote: `_consecutive_failures = 0` / `_circuit_open = False` (:18-19, with `# pylint: disable=invalid-name` suppressing the naming warning the global style triggers)
Two issues: (a) once tripped, the breaker never resets within the process — a transient Overpass outage that clears mid-run permanently disables loipen for all remaining houses; (b) there is no way to reset it for a retry pass or a test without poking module globals. The `_parse` result at :49 also flows unguarded: if Overpass returns valid JSON with an unexpected element shape, `p['lat']` (:90, :107) raises `KeyError` inside `_parse`, which is inside the endpoint loop's try/except at :45-51 (`return _parse(...)` is at :49) — so a parse bug looks like an endpoint failure and counts toward the breaker (:53), eventually opening it for what is a data problem.
Fix: encapsulate in a small class with `reset()`, and separate "network failed" from "parse failed" so parse errors do not trip the breaker.

### B13 (LOW) rodelwelten.py:16 (regex at :14) — `_normalize_length` mangles comma-decimal km
Quote: `m = re.search(r'([\d.,]+)\s*(km|m)\b', raw, re.IGNORECASE)` then `val = float(m.group(1).replace(',', '.'))`
`'1,200 km'` (German decimal) → `float('1.200')` = 1.2 → correct by luck; but `'1.200,5 km'` → `float('1.200.5')` → `ValueError`, uncaught (function has no try) → crashes `scrape()`'s catch-all and returns all-'Error' for the run. Mixed separators are realistic when the site edits its data. LOW because it needs a specific malformed input.
Fix: same thousands-separator-aware parser as B7, wrapped in try/except returning `raw`.

### B14 (LOW) booking.py:107 — train station regex requires a literal `\n` that only appears by accident
Quote: `train_m = re.search(r'Bahn\s*([A-Za-zÄÖÜäöüß][^\n\d]*?)\s*\n\s*([\d,.]+\s*m)\b', text)`
`text = soup.get_text()` (booking.py:26) with no separator: verified that `<span>Bahn</span><span>Lengdorf</span>...<div>650 m</div>` yields `'BahnLengdorf650 m'` — no `\n`, no match, `train_station` stays `'N/A'` unless the station and distance happen to sit in separate block elements. The field also stays 'N/A' even though the broader "Bahnhof" check at :170 would have matched `'Nearby'` — actually :170 does run and overwrites with 'Nearby', so the precise distance is silently lost. Unverified against the live page structure (no network in this review).
Fix: use `get_text('\n')` for the train extraction, or match on the distance element directly.

### B15 (LOW) save_cache in rodelwelten.py:45 / outdooractive.py:34 — crashes when no cache path was set
Quote: `os.makedirs(os.path.dirname(_cache_file), exist_ok=True)`
Verified: `save_cache()` before any `load_cache(path)` (i.e. `_cache_file == ''`) raises `FileNotFoundError` (dirname('') = ''). Reachable if the app calls save before load, or on a first run where `load_cache` was skipped for a provider.
Fix: `if not _cache_file: return` or raise a clear `RuntimeError('load_cache() must be called first')`.

## Implementation gaps

### G1 (MEDIUM) outdooractive.py / rodelwelten.py — duplicated, divergent cache implementations
`load_cache`/`save_cache`/TTL logic is copy-pasted between the two modules (rodelwelten.py:34-47, outdooractive.py:23-36) and both differ from the app-level `cache/houses.json` scheme the README documents ("The file is only replaced when the run succeeds: a run in progress writes `cache/houses.partial.json`"). Neither sled-run cache writes atomically (no partial-file/`os.replace` pattern), so a scrape killed mid-`json.dump` corrupts the cache — which then triggers B3. Concrete fix: one `common.JsonCache(path, ttl)` with the partial-file write, used by both modules.

### G2 (LOW) README vs. fewo.py:119-151 — `curl_cffi` is not in the documented dependency set
README step 1 says `pip install -r requirements.txt`; the curl_cffi fast path is an optional import (:121-146) that silently falls back to plain `requests`, which DataDome reliably blocks. Not a bug (graceful), but the README's Setup never mentions that without curl_cffi the no-driver fewo scrape is effectively dead. One README line ("install curl_cffi for the non-browser fewo path") closes it.

### G3 (LOW) loipen.py:12 — User-Agent URL points to the old org
Quote: `'User-Agent': 'holiday-house-comparison/1.0 (github.com/Gr3yh0und/holiday-house-comparison)'`
The repo now lives under `Gr3yh0und-ORG` (see git remote). Overpass asks scrapers to identify themselves with a working contact URL; the current one 404s. Fix: update the org name.

### G4 (LOW) huetten.py:42 — address drops the country when `addressLocality` is empty
Quote: `result['address'] = f"{city}, {country}" if city else 'N/A'`
When the JSON-LD has a country but no locality, the whole address becomes 'N/A' although the country alone would still be informative, and app.py:155 (`if not address or address in ('N/A', 'Error')`) then treats the house as having no address at all. Fix: fall back to `country` when `city` is empty.

### G5 (LOW) Dead / unreachable code
- rodelwelten.py:52: `return dict(EMPTY, track=[])` — `EMPTY` already contains `track: []` (:30), the override is dead (harmless but misleading about which keys exist; `huts` is not similarly overridden).
- booking.py:157-164 (`m-rs-bed-display` block) and :124-128 (`hprt-roomtype-bed`) both append to `room_config`; on a page where both markers exist the bedrooms are listed twice and `rooms` (= `len(room_config)` at :168) doubles. Not verified against a live page that carries both — flagged as a risk, not confirmed.
- interhome.py:97: `if result['address'] == 'N/A' and ...` — `result['address']` can only be `'N/A'` via the `EMPTY` default; fine, but the breadcrumb branch at :90-95 leaves a *partially* built address (`f"{city}, {country}"` with empty country) non-'N/A', which then blocks the offer-JSON fallback. Use a sentinel or check the parts.

### G6 (LOW) Missing input checks at public entry points
- outdooractive.py:39 `scrape(url)`: no check that `url` is a str/non-empty before `'outdooractive.com' not in url` (a `None` raises `TypeError` before the try at :58 → escapes). Same shape in rodelwelten.py:50.
- huetten.py:227 (`__main__`): `sys.argv[1]` used without a usage guard (contrast outdooractive.py:230-233 which does check) — cosmetic, `__main__` only.
- loipen.py:22 `fetch(lat, lon)`: non-numeric `lat/lon` is interpolated straight into the Overpass query string (:36-40). Overpass answers with an error status → endpoint failure → counts toward the breaker (:53) instead of failing fast. Add `float(lat), float(lon)` validation at the top and return `None` with a clear message.

## Test gaps

Concrete, high-value additions:

1. `huetten._price_for_date` / `huetten._extra_costs_for_persons` / `huetten._sum_prices` — none are tested at all; these are pure functions over HTML fragments and would have caught B2 (KeyError path), B8 (€ after amount) and the `X`-cell/`col >= len(cells)` branches (:157-161) which no test exercises. Add `tests/test_parsers_huetten.py` with a `BeautifulSoup` fixture per case, mirroring `test_parsers_house_pages.py`'s `_FakeDriver` style but without a driver.
2. `booking._rate_rows` — only tested indirectly through one fixture where all three rows carry `Personenzahl`. The `continue` at booking.py:195-196 (row without price or without occupancy) and the non-numeric price path (:199) are untested; add a table with one junk row and assert it is skipped, not fatal.
3. `booking.scrape` booked-out + stray price (B1) — add `BOOKING_BOOKED_OUT_WITH_RECOMMENDATION` (the verified snippet from B1) asserting `time == 'Unavailable'` and `price == 'N/A'`. Without it the test suite would pass even after regressing the guarantee its own comment states.
4. `rodelwelten._normalize_length` — pure function, untested. Add cases `'1.200 m' → '1.2 km'` (currently returns `'0.0 km'`, B7) and `'N/A'/'None'/''` passthrough.
5. `rodelwelten.scrape` / `outdooractive.scrape` cache behaviour — add tests seeding `_cache` with (a) a fresh entry (expect cached data returned *and* mutation of the returned dict not affecting the cache — B5), (b) an entry missing `fetched_at` (expect re-scrape, not `KeyError` — B3). Both are currently completely untested; the modules are not even imported by the test suite.
6. `loipen._parse` / `_parse_way` / `_parse_relation` / `_downsample` — pure functions over a canned Overpass JSON response; untested. The relation-preferred-over-way dedup (:76-81), the `if not geom: return None` branch (:92-93), and `_downsample`'s `max_points` boundary are exactly where a silent regression would distort the maps.
7. `common.normalize_country(None)` — one-line test that today fails with `AttributeError` (B11).
8. Tests that cannot fail / weak assertions: `test_interhome_current_layout` parametrizes `price=''` for the unavailable case, and `_InterhomeDriver.find_element` treats *falsy* text as absent (`if not self._texts.get(css): raise NoSuchElementException`, tests/test_parsers_house_pages.py:155) — so a badge whose text legitimately is `''` and a missing badge are indistinguishable; the Unavailable branch is really only testing "badge missing". Additionally the `person_col` fallback in `huetten._price_for_date:156-158` (more persons than thresholds pick the last column) is untested and silently overprices; add a case with `persons=10, thresholds=[4,8]` once the semantics are decided (last column vs 'N/A').
